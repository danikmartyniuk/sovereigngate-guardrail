# Security Policy

SovereignGate provides configurable data-minimization and technical safeguard controls (supporting GDPR Art. 5(1)(c) & Art. 32). It does not certify compliance or make undetected content safe.

## Supported versions

Security fixes are targeted at the latest published release and the current default branch. Older releases may not receive security updates; upgrade to the latest release when possible.

## Reporting a vulnerability

Please report suspected vulnerabilities privately through [GitHub's private vulnerability reporting](https://github.com/danikmartyniuk/sovereigngate-guardrail/security/advisories/new). Do not open a public issue or pull request with exploit details. If private reporting is unavailable, contact the repository maintainer through [GitHub](https://github.com/danikmartyniuk) and request a private reporting channel.

Include the affected version or commit, impact, and concise reproduction steps. Use synthetic data only: do not include real personal identifiers, prompts, credentials, private keys, or customer data. Reports should avoid destructive testing or access to data that is not yours.

The maintainers aim to acknowledge reports within five business days and coordinate a fix and disclosure timeline with the reporter. Please allow up to 90 days for coordinated remediation before public disclosure; timing may depend on severity and fix availability.
